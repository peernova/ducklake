DuckLake for XVA Desk: Branching for Derivatives Pricing & Risk

Scenario Overview

An XVA desk managing swaptions, caps, floors, and vanilla options needs to run parallel analyses without disrupting production EOD valuations. Teams need isolated environments for model testing, what-if analysis, and stress scenarios.

Key Benefits for XVA/Derivatives

  • Model Testing - Test new SABR calibrations without affecting production XVA
  • What-If Analysis - Add hypothetical trades, see incremental CVA impact
  • Stress Testing - Shock curves and spreads, compare to base case
  • Audit Trail - Time travel to any historical valuation date
  • Zero Data Copy - Branches share underlying Parquet files

Model Testing Branch

Goal: Quant team tests new SABR calibration with higher vol-of-vol (nu parameter).
Business Context: The quant team believes the current SABR calibration underestimates vol-of-vol. They want to test new params and see the XVA impact without affecting production.

Terminal 2 (model_test)

-- Connect and switch to model_test branch
CALL ducklake_use_branch('db', 'model_test');

-- Delete old calibration for today
DELETE FROM models.sabr_params WHERE calib_date = '2024-01-16';

-- Insert new test calibration with higher vol-of-vol
INSERT INTO models.sabr_params VALUES
    ('2024-01-16', 'USD_SWAPTION', '1Y', 0.0330, 0.5, -0.28, 0.50),  -- nu: 0.41 -> 0.50
    ('2024-01-16', 'USD_SWAPTION', '5Y', 0.0290, 0.5, -0.32, 0.45),
    ('2024-01-16', 'EUR_SWAPTION', '1Y', 0.0360, 0.5, -0.22, 0.52);

-- Recalculate XVA with new model (simulated results)
DELETE FROM results.xva_daily WHERE valuation_date = '2024-01-16';

INSERT INTO results.xva_daily VALUES
    ('2024-01-16', 'TRD001', 'CPTY001', 'MTM', 1350000.00, 'USD'),   -- higher due to vol
    ('2024-01-16', 'TRD001', 'CPTY001', 'CVA', -52000.00, 'USD'),    -- higher CVA
    ('2024-01-16', 'TRD002', 'CPTY001', 'MTM', 3450000.00, 'USD'),   -- swaption more sensitive
    ('2024-01-16', 'TRD002', 'CPTY001', 'CVA', -145000.00, 'USD');

-- Compare with production
SELECT 'model_test' as branch, measure, SUM(value) as total
FROM results.xva_daily WHERE valuation_date = '2024-01-16' GROUP BY measure
UNION ALL
SELECT 'main', measure, SUM(value)
FROM results.xva_daily AT (BRANCH => 'main') WHERE valuation_date = '2024-01-16'
GROUP BY measure
ORDER BY 2, 1;

Value Assessment: Is Branching Worth It?

Where Branching Adds Clear Value

  • Pre-Trade Analysis - Sales can test hypothetical trades without sandbox copies
  • Model Validation - Quants test new calibrations against production data
  • Regulatory Stress Tests - Risk runs scenarios with full audit trail
  • EOD Parallel Runs - Compare old vs new methodology before cutover
  • No Infrastructure Overhead - No separate databases, no data copies

Where Traditional Approaches May Be Better

  • ✗ Real-time Pricing - Latency requirements favor kdb+/custom engines
  • ✗ Massive Simulation Data - TBs of paths per day may need specialized storage
  • ✗ Existing Infrastructure - Shops with kdb+/Snowflake already invested

Best Fit

  • Batch analytics / EOD valuations
  • Smaller shops without enterprise infra
  • Research / prototyping environments
  • Regulatory reporting with audit needs

Not Ideal For

  • Sub-millisecond pricing requirements
  • Streaming Greeks / real-time risk
  • Multi-TB simulation path storage
Bottom Line: DuckLake branching shines for batch XVA workflows where teams need isolated environments for model testing, what-if analysis, and stress scenarios - all without the overhead of separate databases or data copies. The killer combo is branching + time travel + Iceberg format + runs anywhere (laptop to cloud).
